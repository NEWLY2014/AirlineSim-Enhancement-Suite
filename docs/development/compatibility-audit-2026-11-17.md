# 兼容性与并发一致性排查（2026-11-17）

基于 0.9.0 后的本地工作树。本文包含排查修复及随后统一存储、自动关闭的修改，版本号保持不变，不涉及发布新版本。此次覆盖源码中的主要兼容边界，并运行全部现有自动化测试；不等于已在所有真实游戏页面和浏览器版本中验证。

## 已确认并修复

### 1. 旧格式开关的读取规则不一致

部分界面、自动关闭和自动采集使用 JavaScript 真值判断，字符串 `"0"` 因而被当成开启；Inventory 自动调价已有另一套判断规则，造成界面与执行不一致。

- 在 `helpers.ts` 统一开关读取：仅 `true`、`1`、`"1"` 表示开启。
- 应用于 Settings、Inventory 历史显示、FlightInfo 自动关闭及航班/竞争对手自动采集。
- 不重写用户已存储的设置；读取时兼容旧格式。
- 回归验证：旧格式开关、历史显示，以及既有设置页面测试。

### 2. 旧 Inventory 页面可以覆盖其他页面的新记录

页面初始化后一直持有旧的整条航线记录。保存快照、写入待确认调价标记或确认调价时，直接覆盖存储，可能抹掉另一个页面刚保存的状态。

- 三条写入路径统一通过后台串行处理，并比较页面读取的原始记录与当前记录。
- 检测到冲突时停止保存并提示刷新；自动调价在保存失败时不会继续提交价格。
- 相同结果的重复写入允许成功，覆盖“已保存但回执丢失”的重试情形。
- 回归验证：两个页面竞争首次写入、旧页面覆盖确认记录、冲突后无价格提交、重复回执及非 Inventory 页面调用限制。
- 取舍：采用整条记录冲突检测；即使两个页面改的是不同日期，也可能要求刷新，优先保护调价确认状态。

### 3. 竞争对手自动采集结束时覆盖新历史

自动采集完成后，旧页面将本地保存的整条竞争对手记录重新写入，只为清除 `autoExtract`，可能覆盖其他页面采集的新历史。

- 改用后台差异合并，将原始存储记录作为比较基线。
- 特别保留旧版无 owner 键的迁移行为：新 owner 键写入成功，旧记录不删除。
- 回归验证：竞争对手历史并发合并、自动采集流程和旧键迁移。首次全量验证暴露了迁移基线问题，修正后全量复跑通过。

## 一并验证的前序 429 修复

- 同一冷却期内多个限流响应不再逐个翻倍等待时间。
- 无服务端明确期限时，从 5 秒开始，后续限流轮次依次为 10、20、30 秒。
- 服务端 `Retry-After` 指定更长等待时仍遵守；请求执行结果不明的过期许可恢复仍保留 60 秒保护间隔。
- Inventory 等待信息显示冷却截止时间；会话冷却跨刷新保留，到期自动恢复。

这些是此前未发布修改，本次没有将它们重复计作新发现。

## 后续技术债处理

### 统一扩展存储写入口

- `chrome.storage.local` 的 `set/remove/clear` 只保留在 `storage-coordinator.ts`；增加架构回归，防止页面重新绕过后台写入。
- 安装时合并默认设置、设置更新、记录补丁、采集保存、日志追加、语言/版本偏好、排班模板、工资记录及 Options 操作共用 `AESStorage.run` 串行事务。
- 页面使用受范围限制的 `AESPersistence` 客户端。旧备份字段与记录键保持兼容；航班记录及摘要保存携带读取基线，拒绝冲突修改。
- 日志在后台读取最新记录再追加，多页面同时记录不会互相覆盖；仍保留每日最后 300 条。
- 备份替换的恢复副本、写入、读回校验和清理在一个事务内完成。恢复被打断后，持久化恢复副本会阻止普通写操作；后台重启后仍生效，直至用户完成恢复或明确清空数据。
- 合并恢复和替换恢复都校验保留键；仅 Options 页面可执行恢复/清空，普通游戏页面不能调用这些操作。
- 此处的收口范围是扩展持久存储 `chrome.storage.local`。队列及任务所有权继续使用各自后台模块的 `chrome.storage.session`；游戏源内用于同步查找航空公司和 ORS 翻页的旧 `localStorage` 缓存不属于备份记录，本次未改变其存储位置。

### 统一自动关闭

- Inventory 与 FlightInfo 共用 `AES.closeSavedTab` 和后台 `tab-close.ts`，移除 FlightInfo 的 `window.close()`。
- 后台读取对应开关，验证来源标签页、URL、文档 ID 和页面令牌；确认回执后再次检查是否发生导航。
- 只在保存成功后申请关闭；关闭被取消不报保存失败，实际关闭错误单独显示。
- Chromium 扩展回归覆盖 Inventory 确认后关闭和普通打开的 FlightInfo 标签页保存后关闭；单元回归覆盖旧开关、导航变化、保存失败和关闭失败。

## 验证边界

- 页面解析仍依赖游戏 DOM、原生按钮及 Wicket 响应。固定夹具不等于真实游戏全部语言、页面变体、后台冻结/丢弃标签页和不同 Chrome 版本均已验证。
- 备份事务不会与其他扩展持久写入交错，但不能撤销已经发到游戏服务器的票价、工资或排班请求。恢复完成后应按界面提示刷新已打开页面。
- 未为测试更改线上票价、工资或排班；真实服务器限流节奏不由夹具测试证明。
